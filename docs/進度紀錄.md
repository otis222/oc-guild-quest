### 2026-10-10　T1 狀態、儲存與事件紀錄
- 做了什麼：
  - `src/core/types.ts`：照企劃表 v1.1 的 7.2（`OCProfile.sprite` 是必填）。
  - `src/core/storage.ts`：用 `idb-keyval@6.3.0`（允許清單內，鎖定版本），資料庫叫 `oc-guild-quest`，不用預設名稱，因為 GitHub Pages 上同一個帳號的專案共用同一個網域。key 有三種：`state`（整個 GuildState）、`events`（事件陣列）、`photo:<id>`（照片 Blob，狀態裡只放 id）。另外寫了 `putPhoto`／`getPhoto`。
  - `src/core/state.ts`：
    - `STATE_VERSION = 1` 和 `migrate()`：之後改結構時，版本號加一、補一個升級函式，舊存檔讀進來會自動升級。存檔比程式新或格式不對時會丟錯，不會被新狀態蓋掉。
    - `loadState`、`saveState`、`updateState`。`updateState` 在同一個 IndexedDB 交易裡「讀最新存檔 → 套用操作 → 寫回」，開兩個分頁也不會拿舊資料蓋掉新進度。
    - 純函式操作：`createGuildState`、`addCommission`（`cellIndex` 照 7.4，是同課程的第幾張 mod 3）、`completeLevel`（同一關完成兩次只算一次；交件關不能用它完成）。
  - `src/core/events.ts`：`logEvent`、`loadEvents`，同時記多筆也不會掉。
  - `src/core/id.ts`：id 用時間＋亂數。不用 `crypto.randomUUID()`，因為手機用區網 IP（http）連 dev server 時不能用。
  - `src/main.ts`：每次打開頁面記一筆 `app_opened`。IndexedDB 寫不進去只在主控台警告，不影響大廳。
- 怎麼驗收的：

## 之後再做（不在目前任務卡範圍內的想法）

- 升級 Node 24 LTS 後：Vite 6 → 8、Vitest 3 → 5（順便清掉 `npm audit` 的警告）。
- 頁面在背景分頁或面板被隱藏時打開，會停在「場景載入中…」直到切回前景（`img.decode()` 和 requestAnimationFrame 被瀏覽器暫停）。legacy 也一樣，目前不影響使用；T8 做手機版時可以留意。
- 375 寬時左上標題「OC 巡展廣場 DEMO」會換成兩行（legacy 原樣，T2 沒有動標題）。要不要改成遊戲名稱、順便調整，可以跟大廳招牌（T6 顯示等級）一起決定。
- 呼叫 `navigator.storage.persist()`，降低瀏覽器自動清掉資料的機會（Safari 對一段時間沒互動的網站會清資料）。Firefox 桌機版會跳詢問視窗，所以先不做，T8 再決定。
- 開兩個分頁時資料不會互相蓋掉，但另一個分頁的畫面要重新整理才會更新；需要的話可以用 BroadcastChannel 通知。
- IndexedDB 打不開時（例如部分瀏覽器的私密模式），目前只在主控台警告；可以在畫面上加一句說明。
